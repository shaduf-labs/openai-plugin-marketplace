Distribute and maintain a plugin

Choose the release channel and change process before making access promises. A catalog entry, workspace share and public listing are not interchangeable.

Three channels to compare

Local / repository catalog
A catalog points to the source package for development or team use. Preserve existing catalogs; version source changes, follow restart/new-session guidance and retest. It is not universal public publication.
Authorized workspace import / sharing
Admin/role controls, repository access and service connections remain separate. Sharing does not automatically install or grant provider access. Imported raw MCP configurations remain Desktop-only even for HTTPS.
Universal public directory
A complete reviewed release reaches the explicit Publish stage. Exact-name/direct-link availability is distinct from enhanced distribution, which is discretionary and not requestable.

Bundled changes versus deployed tool changes

Skill / metadata / asset change
Version the package and prepare a new ZIP through the required checks/review route. For a local catalog, update the pointed-to source and verify the actual loaded version in a fresh session.
Hosted MCP implementation
Server code stays deployed, not frozen inside the ZIP. Current guidance describes daily scans and eligible tool-update approval. Preserve approved contracts, inspect held/new-tool status and test behavior after deploy.
Connected roadmap
No supported addition of MCP to an existing skills-only public listing today. Resolve that identity/component decision before making a public upgrade commitment.

Keep the endpoint conflict visible

Do not invent a URL-change rule.

Submission guidance says its current update flow cannot change an existing MCP URL and directs readers to support. Review guidance describes a new plugin for origin changes and a version for path changes. Preserve the production endpoint and get portal/support confirmation before moving it. A held metadata update does not freeze deployed server code.

Release and access worksheet

Channel and audience
Local/repo, authorized workspace or public? Who can discover, install and connect independently?
Identity and component roadmap
List public identity, skill/MCP/UI components and any future connection plan. Name unsupported upgrade assumptions.
Source and version
Record repository/package version, bundled artifacts and the fresh-session verification procedure.
Regression evidence
Link actual behavior records for activation, missing/negative input and action boundaries. Planned tests are not passes.
Service continuity
Record stable endpoint, supported tool contracts, provider permissions/entitlements and the responsible maintainer. Seek clarification before endpoint moves.
User-facing change
Explain what changed, what users must reinstall/reconnect or retest, and how to revoke retained access. Do not imply publication guarantees access.

Custom GPT migration as an access-continuity task

Custom GPT creators: scope matters.

Current migration guidance addresses Enterprise admins/creators, including public GPTs in affected Enterprise workspaces. Other-plan sharing/timelines may differ. It gives no calendar deadline. Instructions/reference material can migrate; custom actions need rebuilding and selected models do not carry over. Retest intended-user access; sharing, installation and service permissions remain separate. Custom GPT migration guidance. Checked 29 Sep 2026.

  1. Confirm scope. Establish the affected Enterprise workspace, creator/admin role and intended users; do not infer an all-plan deadline.
  2. Inventory what translates. Track instructions/reference material separately from custom actions and model choice; rebuild the actions rather than assuming transfer.
  3. Retest the route. Verify behavior, sharing, installation and provider access for the actual intended users.
  4. Plan maintenance. Preserve the new source/version and unresolved access conditions before declaring continuity.

This is a planning checklist, not an executed migration or a new migration service. The saved source provides no calendar transition deadline.
