Missing an OAuth client-ID setting? Establish the contract before retrying

Public remote-MCP draft / ChatGPT auth detail · documentary checks 9 October 2026 · portal/connect/use NOT RUN.

Registration contract → exact callback → next owner. Do not guess a field or repeatedly rewrite ZIPs. The precise predefined-client control is not established by the inspected public guidance or our unavailable portal access. Missing evidence does not prove the control is absent.

Motivated by one unverified problem report, not our reproduced failure or a confirmed platform defect. This triage order and redacted escalation packet are our synthesis, not an official required form or tested fix.

  1. Save the failing boundary. Keep the exact redacted nonsecret message, stage, surface and selected authentication/registration mode. Required-field validation is not user login, token exchange, tool scan or review. Documented public setup: MCPs → select server → Connect; inspect MCP Server URL, Authentication and applicable settings. These handles do not name the predefined-client field. Submission · Connect and scan.
  2. Confirm the registration contract with its authorized maintainer. A predefined selection needs the intended existing provider registration/client ID confirmed before asking where it belongs. Use what the provider actually implements; do not substitute another kind of ID or switch modes blindly.
    Different contracts, not interchangeable credentials

    Client ID Metadata Document (CIMD) uses an HTTPS document URL as identity; Dynamic Client Registration (DCR) obtains and reuses a generated client. Check real resource/provider discovery, accepted token-endpoint authentication methods and S256 support for Proof Key for Code Exchange (PKCE). CIMD needs advertised support and document fetching; DCR needs a registration endpoint and login-enabled client. Predefined credentials do not mean the unsupported machine-to-machine client_credentials grant.

    Authentication · OAuth metadata / Client registration / Client identification, Troubleshooting · Authentication problems.

  3. Compare this connection’s exact callback. Use the production redirect shown on its MCP management page and the authorized provider allowlist—not a sample or wildcard. Missing management output stays UNKNOWN; never bypass validation or transfer a ChatGPT callback to another host.
    A stable callback needs real issuer behavior

    Stable eligibility requires advertised issuer identification. The authorization-server metadata issuer must match that server’s entry in the MCP protected-resource metadata authorization_servers list; every successful/error authorization response iss must match that issuer—not the MCP resource URL. A flag alone is insufficient.

    Authentication · Protect callbacks with issuer identification / Redirect URL.

  4. Repair an evidenced boundary—or stop for clarification. Provider/client/auth-method/redirect mismatch → authorized provider maintainer. Missing or contradictory required portal control → OpenAI support clarification with plugin/draft ID, stage, selected mode and redacted error. Submission asks for the plugin ID; the broader packet is our advice. No contact occurred.
    Retained-client errors and reviewer access are separate

    For an existing DCR connection returning invalid_client, check/restore the retained client and any secret rather than create another. An expired access token is different. This conditional advice is not the reported blocker’s diagnosis. Reviewer test-account credentials belong separately in Review details, not the ZIP or in place of OAuth registration.

    Troubleshooting · Authentication problems / Escalation, Submission · Review information / Support.

    Do not expose credentials/private logs, arbitrarily reset clients, or downgrade required authentication.

  5. After legitimate correction, retry the right gate. Use documented Reconnect for connection attention or applicable Rescan for server/tool findings; inspect results before submission. Custom-development Refresh is different. Separately establish user consent/resource access, reviewer access and useful workflow results. Connection, scan, review, approval and chosen Publish are not equivalent. Submission · Connect and scan, Connect and test · Refresh / Evaluation.

Genuine alternative: if no customer-specific data/action is needed, an ordinary prompt/skill or existing authorized integration may suffice. Untested alternatives, not drop-ins; never disable required authentication to expose protected work.
