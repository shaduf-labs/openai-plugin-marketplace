OpenAI plugins: the developer guide

A plugin is an installable package of reusable task instructions, tool connections, or both. The universal directory is their shared public catalog for supported ChatGPT and Codex surfaces—not a universal execution or access guarantee.

Choose your next developer task

  1. Choose architecture

    Decide what needs a skill, a live connection or UI; check the actual host.

  2. Build a plugin

    Inspect the manifest/skill source, download it and check host prerequisites before attempting private installation.

  3. Test and debug

    Run scoped offline checks, repair a packaging failure and prepare separate host evidence.

  4. Security and permissions

    Write the data, authorization and irreversible-action boundary.

  5. Submit and review

    Prepare missing listing and reviewer evidence; keep upload, review and Publish separate.

  6. Distribute and maintain

    Choose local, workspace or public distribution and a versioned update plan.

  7. Business constraints

    Check commerce policy and test a useful-workflow hypothesis—not an earnings promise.

  8. Research

    Read dated studies, their evidence methods and unresolved conflicts.

  9. For AI agents

    Retrieve the right route without dropping exclusions or evidence status.

What public publication would add

Local tests do not publish a plugin. The public path is a complete ZIP, automated checks, final submission, review, approval and an explicit developer Publish action. A skills-only public listing cannot currently gain MCP later; plan the component roadmap first. A public listing does not grant service access or guarantee discovery, approval timing or revenue.
